macOS · zsh · Claude Code CLI

Claude Code on Mac

Install, sign in, and keep control of what Claude can read, run, and send. A quick reference built from one setup conversation.

~/Projects/your-project % claude
Setup

Install in four steps

  1. Install the CLI

    Recommended · native installer 
    curl -fsSL https://claude.ai/install.sh | bash
    Homebrew 
    brew install --cask claude-code
    npm · Node 18+, no sudo 
    npm install -g @anthropic-ai/claude-code

  2. Check the install

    claude --version
claude doctor

    If you see command not found, open a new terminal, or add ~/.local/bin to PATH in ~/.zshrc.

  3. Start it in a project and sign in

    cd ~/Projects/your-project
claude

    The first run opens your browser to sign in with a Claude plan or an Anthropic Console account. Switch accounts later with /login.

  4. Finish setup

    • /init writes a CLAUDE.md with project notes.
    • /terminal-setup makes Shift+Enter add a new line.
    • /config sets theme and model; /ide connects VS Code or JetBrains.
    • Updates install on their own. Run claude update to update now.
Permissions

Permission modes

Press Shift+Tab to cycle modes. Bypass mode can only be turned on with a flag at launch.

ModeWhat happens
DefaultAsks before edits and most shell commands.
Accept editsEdits files without asking. Still asks before shell commands.
Auto fewer promptsA safety check approves routine actions and stops risky ones.
PlanRead-only. Claude researches and proposes a plan.
Bypass YOLONo prompts, no checks. Started with --dangerously-skip-permissions. Use it only in a container or throwaway VM.
Privacy

Control which files Claude can read

See every action

Every file read, edit, and command appears in the terminal. Press Ctrl+O to see the full transcript.

Limited to the project

Claude can freely read only the working folder and folders added with /add-dir. Review the rules with /permissions.

OS-level sandbox

Run /sandbox. macOS Seatbelt then limits shell commands to allowed folders and websites.

Block sensitive paths

Deny rules apply in every mode except bypass.

~/.claude/settings.json 
{
  "permissions": {
    "deny": [
      "Read(~/.ssh/**)",
      "Read(~/.aws/**)",
      "Read(./.env)"
    ]
  }
}
Network

Internet access and your own model

The model runs on Anthropic's servers, so Claude Code needs the internet for every message, for signing in, and for updates. Files Claude reads are sent along with the conversation. It has no offline mode.

You can point it at a model you host, if that model's server accepts the Anthropic Messages API format (use a proxy like LiteLLM for OpenAI-style servers). Anthropic doesn't support this setup, and the model must handle tool calls and long context well.

# point Claude Code at your own server
export ANTHROPIC_BASE_URL="http://localhost:8000"
export ANTHROPIC_AUTH_TOKEN="your-server-token"
export ANTHROPIC_MODEL="my-model-name"
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
claude
If something goes wrong

You shared a token or password

Treat it as exposed and rotate it now.

Once sent, it's on Anthropic's servers under your retention policy, and saved in plain text in ~/.claude/projects/.

  • Revoke the token and create a new one in the service it belongs to.
  • Find and delete the local copy of the conversation:
grep -rl "part-of-the-secret" ~/.claude/projects/
  • If it was committed, rotate it first, then clean the history with git filter-repo.
  • Next time, give Claude the variable name, like $GITHUB_TOKEN, not its value.
